03 — Problem & solution

Simplifying IoT Device Monitoring

Operators had the data, but no quick way to get answers from it.

The problem

Every investigation started in a spreadsheet.

100,000 devices in one 22-column Excel file. Tracing a faulty site to a customer took hours.

  • One faulty site showed up as hundreds of red rows.
  • Device status and SIM Applet update status were easily confused.
  • Updates had no limit, preview or confirmation.
The solution

Monitor, investigate and manage devices in one place.

Designed to show within seconds if anything is wrong, then narrow it down from region to site to device.

  • Overall device health on one screen.
  • Region → site → device drill-down, with affected customers.
  • Updates capped at 1,000 devices per session.
Find the faulty network site~2 hrs → 3 clicks
What operators look through100K rows → 9 screens
Bulk update safety limitnone → 1,000 / session

“~2 hrs” is survey-reported. “3 clicks” is the prototype path, not a measured time.

06 — SWOT analysis: strengths, weaknesses, opportunities, threats
S

Strengths

  • One view for device, SIM Applet and network health
  • Based on the real master file, with clear labels for sample data and preview features
  • Optimized tables keep 100K+ rows fast
W

Weaknesses

  • Uses a sample dataset, not live data from devices
  • No backend yet, so AI insights are a preview only
  • The SIM Applet update count is a fixed figure, not connected to live SIM systems
O

Opportunities

  • Connect live data from devices
  • Let users ask questions in plain language using an AI model
  • Add customer-facing views for account teams
T

Threats

  • Vendors bundle their own portals with their devices
  • Teams are used to working in spreadsheets
  • 100K+ live devices will need a stronger backend

An example

If 10,000 devices go offline, the engineer narrows it down: region, then site, then devices and customers.

Circle (region)

A large service region. The 7 cities sit in 4 circles.

BTS (network site)

The radio equipment at a cell site. Many failures behind one BTS point to the site.

Device status

Active: working. Degraded: working poorly. Out of Reach: unreachable. Blacklisted: blocked.

Applet version

v2.1.0 is the target; 37,088 devices are on older versions.

Eligible devices

Only devices compatible with the target version can be selected.

Bulk update

Update many devices in one action, after confirming.

1,000-device limit

A bad update reaches at most 1,000 devices, not the whole network.

IMEI and ICCID

IMEI identifies the device; ICCID identifies its SIM card.

Data source

Where new device records come from. Invalid ones go back for fixing.

Automatic configuration

Default mapping rules give each new device its SIM Applet setup.

Conflicting configurations

When two rules disagree, a person reviews the device.

Scroll sideways on small screens. The prototype uses sample data; updates aren’t sent to real SIMs.
