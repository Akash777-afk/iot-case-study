03 — Problem & solution

A million rows. One answer.

Operators had all the data and none of the answers. The fix was less about adding features and more about the order in which questions get answered.

Problem statement

Every incident started with a spreadsheet.

NOC operators tracked 1,000,000 IoT devices in one 22-column Excel file. Finding which tower was failing which customer took hours.

  • One bad BTS showed up as hundreds of separate red rows.
  • “Status” and “applet update status” looked alike and got mixed up.
  • Bulk applet updates had no limit, preview or confirmation.
Solution statement

See it, trace it, fix it — in one place.

A dashboard that answers “is anything wrong?” in five seconds, then lets operators drill from a circle to a BTS to the exact devices, and run capped, confirmed SIM Applet updates on real data.

  • Fleet health on one screen, numbers that animate when data changes.
  • Circle → BTS → device drill-down with customer impact.
  • Bulk updates capped at 1,000 devices per session.
Find the failing BTS~2 hrs → 3 clicks
What operators scan1M rows → 9 screens
Bulk update guardrailnone → 1,000 / session

06 — SWOT analysis
S

Strengths

  • One view for device, applet and network health
  • Built on real master data with honest fallbacks
  • Virtualized tables keep 100K+ rows fast
W

Weaknesses

  • Runs on a sample, not live telemetry
  • No backend yet: AI insights are a preview
  • Applet rollout is a fixed figure today
O

Opportunities

  • Plug in live device streams
  • Plain-language questions through an LLM
  • Customer-facing views for account teams
T

Threats

  • Vendors bundle their own portals
  • The spreadsheet habit is hard to break
  • 1M+ live devices need a stronger backend

09 — Low → high fidelity

From paper to pixels.

Every screen started as a pen sketch, then became a greyscale high-fidelity wireframe with real labels and layout before any color. Pick a screen to compare the two.

Filters above everything

Customer, device type, location and time sit on top, so one change updates every card.

Nine cards, one grid

Each card answers one question, in a chart picked for that data.

Download on each card

Every card exports its own live data, with no trip to a reports page.

Live update in reach

The sidebar footer shows when data last refreshed.

Name first

Every support call starts with “which device?”, so its name and config lead the page.

Applet beside network

Version and network health sit side by side, so a failed update is easy to tell apart from bad signal.

Issues in their own rows

Network issue and data security get one row each, which stays calm when there is nothing to report.

A way back

“Back to dashboard” stays top right, so a deep dive never strands the operator.

List before action

Device, ID and customer come first, so operators see what they are about to touch.

One or many

Each row has its own Update button, and “Bulk update” sits top right for the whole selection.

Confirm in a modal

Eligible and selected counts are shown before anything is pushed to a device.

Capped by design

At most 1,000 devices per session, so a bad build can’t reach the whole fleet.
